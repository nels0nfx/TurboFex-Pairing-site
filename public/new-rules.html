Developer rules

Plugins run on other people's bots and in their groups, so the rules are strict and simple. Every plugin is read by the owner before it is published.

1. What a good plugin is

  • It does what its name and description say, nothing more.
  • It asks only for the permissions it really uses.
  • It is useful: it adds something TurboFex does not already do.
  • It is yours, or you have the right to share it. Say so in the README if it builds on someone else's work.

2. What is not allowed

  • Spam: flooding groups, sending messages nobody asked for, or advertising.
  • Scams and tricks: phishing, fake giveaways, fake "verification", or anything that tries to get money, passwords or codes from people.
  • Harmful or illegal content: adult content, hate, threats, harassment, or anything illegal.
  • Hidden behaviour: scrambled or hidden code, or doing something the description does not say. Code must be readable.
  • Collecting people's data: numbers, messages or names sent to another website without a clear reason that is written in the description.
  • Pretending: using the TurboFex or WhatsApp name or logo as if the plugin were official.
  • Misusing group tools: removing members or changing a group in ways the group's admins would not expect.
  • Wasting the bot's power: endless loops or heavy work. The bot stops a plugin that runs too long.
  • Copying: publishing another developer's plugin as your own, or an almost identical copy of one already in the store.

3. What the owner checks

  • Every permission fits what the plugin says it does. The more powerful the permission, the closer the look.
  • The automatic checks and a test run of every command and event, in a pretend chat.
  • The plugin was tried on a real bot.
  • The description is honest, and the plugin does not clash with another plugin or with a TurboFex command.

Use the Playground before you send a plugin. If it fails there, it will fail the review.

4. Decisions

  • Approved: the plugin goes live in the store.
  • Changes asked: you get a short note on what to fix. Fix it and send it again.
  • Rejected: you get the reason. You can send a corrected plugin as a new version.

5. After it is published

  • Updates are reviewed too. A new version that asks for more permissions or more websites is looked at again before it goes live.
  • Withdrawn plugins disappear fast. If a plugin breaks these rules, or turns out to be unsafe, the owner can withdraw it at any time. Bots remove a withdrawn plugin by themselves, usually within minutes, and tell their owners.
  • Keep it working. Plugins that keep failing are switched off by the bot. Fix problems quickly.
  • Questions or disagreement? Write to us through the Support page.
